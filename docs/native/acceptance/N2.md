## Architecture and source scope

The 171 MiB GPT regular-file image has protective MBR, matching primary/backup
GPT metadata, and these exact roles:

| Role | Offset / size | N2 behavior |
| --- | --- | --- |
| BIOS_GRUB | 1 MiB / 1 MiB | Normal GRUB BIOS embedding area |
| BOOT / ESP | 2 MiB / 16 MiB | FAT kernel/config and UEFI fallback loader |
| SYSTEM_A | 18 MiB / 60 MiB | Active ext4 locked-release system, still writable |
| SYSTEM_B | 78 MiB / 60 MiB | Zero-filled, unformatted, no-automount reserved slot |
| DATA | 138 MiB / 32 MiB | Persistent ext4 mounted at `/var/lib/moos` |

DATA root, `identity/` and `config/` are root:root 0700; schema `state-version`
and `identity/installation-id` are root:root 0600 single-link regular files.
Schema is exactly `1\n`; identity is a locally generated UUIDv4 with a newline.
The distribution has no installation ID. Fresh copies initialize independently;
already initialized DATA copies retain their identity. It is not a credential.
Packages/apps/instances/updates/recovery are future-reserved boundaries, not
created fake functionality. `/run` and entropy seed state are transient.

Boot locates DATA on the actual SYSTEM_A disk, mounts ro/noload before
schema/ownership/identity checks, then permits writes with nodev/nosuid/noexec.
Missing, ambiguous, corrupt, mismatched or incompatible DATA blocks state and
retains diagnostics. No boot formatter, filesystem repair, identity replacement,
migration or downgrade is implemented. A post-rw failure revokes writes.
Future consumers must require the transient READY state; none is added here.
SYSTEM_B has no active/verified status, slot switch, try boot, health confirmation
or fallback. N2 is explicitly not A/B update support.

Runtime source: Native defconfig/BusyBox fragment, init/entropy hooks,
post-build/post-image, GPT and GRUB configuration. A narrow GRUB build-tool
patch avoids host-root probing for whole regular BIOS image files and leaves
normal embedding checks/blocklist refusal intact. Device maps are canonicalized
by upstream GRUB; caller checks enforce output link safety.

Acceptance source: safe writable-copy option in the Native runner, bounded GPT
inspection, positive/negative boot, persistence/fault tests and policy CI.
Fixed telemetry/poweroff is injected offline only into private SYSTEM_A copies;
the distribution was inspected to contain no such probe, Python runtime or GRUB
target tools. No Rust, stable CLI/Protocol, Gateway, Personal launcher/profile,
privileged installer, source manifest, trust anchor or signed fixture changes.

## Build and repeated generation

The complete build and final rebuild ran as an unprivileged Windows/WSL2 Ubuntu
builder, using pinned Buildroot 2026.05.1 and existing toolchain/cache:

```sh
./scripts/build.sh --target native --jobs 2
```

The first GPT build exposed GRUB's unrelated host-root discovery dependency;
the tracked build-tool patch resolved it without root/loop devices or forced
blocklist installation. An initially mode-000 system mountpoint also prevented
unprivileged rootfs rsync; it is now a buildable mode-555 system mountpoint,
with readonly runtime blocking on DATA failure. No permissions were widened
on the Host. Existing package build state was resumed, not broadly deleted.

After the final schema/identity encoding fixes, the complete command above
succeeded and was repeated twice. `cmp` verified each of the following artifacts
byte-identical to the first final generation, with epoch 1790812800/UTC:

SYSTEM_B/DATA/GPT space; 256 MiB VM allocation is not a hardware RAM minimum.
Images, firmware, logs, caches and toolchains remain generated/ignored.

## Exact Native checks

```sh
python3 tests/native_config.py
python3 tests/native_layout.py
python3 tests/native_grub.py
python3 tests/docs_links.py
python3 tests/native_boot.py --boot bios --network user --log n2-final-bios-console.log
python3 tests/native_boot.py --boot uefi --network user \
  --uefi-code /usr/share/OVMF/OVMF_CODE_4M.fd \
  --uefi-vars /usr/share/OVMF/OVMF_VARS_4M.fd --log n2-final-uefi-console.log
python3 tests/native_boot.py --boot bios --network none --log n2-final-none-console.log
python3 tests/native_boot_negative.py
python3 tests/native_persistence.py
python3 tests/native_persistence.py --boot uefi \
  --uefi-code /usr/share/OVMF/OVMF_CODE_4M.fd \
  --uefi-vars /usr/share/OVMF/OVMF_VARS_4M.fd
python3 tests/native_state_negative.py
```

The firmware paths are this Ubuntu distribution's tooling examples, not repository
contracts. QEMU 11.0.3 ran rootless through Bubblewrap with TCG, one CPU, 256 MiB
and serial/headless output, never direct `-kernel`. BIOS used SeaBIOS 1.17.0;
UEFI used OVMF. Both reached GRUB, Linux 6.18.43, SYSTEM_A, DATA READY,
MOOS Native `0.1.0-dev`, backend/architecture identity and release login.
Explicit user NAT obtained DHCP 10.0.2.15. Disabled networking also booted.
Actual blank-password root login was rejected; normal acceptance terminated
QEMU via console quit with exit zero and unchanged disk/firmware hashes.

GPT tests validate CRCs, primary/backup agreement, exact GUIDs/types/ranges,
reserved B and unsafe/truncated/missing/duplicate role rejection. Policy checks
execute unsafe generated-output symlink/hardlink rejection before writes and
writable-runner rejection of canonical-path, symlink, hardlink and root usage.
GRUB embedding succeeds on regular GPT copies and refuses missing/undersized
BIOS_GRUB. Destroyed BIOS code and absent SYSTEM_A fail real disk boot; no B fallback.

Final persistence and DATA fault gates: **PASS on the final image**.
BIOS and UEFI each proved mounted writable DATA, stable identity/marker after
reboot and SYSTEM_A refresh, and distinct fresh-clone identities. All ten real
degraded cases passed: missing DATA, ambiguous role, corrupt filesystem, wrong
filesystem UUID, newer schema, malformed schema bytes, incomplete identity,
invalid identity links/text and failure after rw. Rejected DATA remains readonly
and byte-unchanged; the post-rw case permits normal filesystem metadata changes
but verifies the identity is retained and writes revoked. Successful writable
tests observe orderly guest poweroff/zero QEMU exit. They use
only private mode-700 `/tmp/moos-native-persistence-*` directories and single-link
mode-600 regular copies. Canonical distribution and firmware templates stay unchanged.

## Independent review and cleanup

Independent second-agent reviews inspected the actual source diff. Findings on
post-rw failure, generated-output link safety, interrupted identity and malformed
schema encoding were resolved. The final source review reports no remaining
blocking implementation/security/architecture finding. Image acceptance is
primary-agent observed evidence, not a reviewer-run hardware test.

Native architecture and N1/N2 evidence now live under docs/native; docs/README
indexes discovery/contracts/history, and the structure audit records deferred
cleanup. N1 evidence remains dated historical context. Root contracts, release
members, manifest pins and externally signed fixtures retain their bytes/paths.
Old audits, broad line-ending changes, and aesthetic scripts/tests reorganization
were deliberately not performed. `.gitignore` covers all generated Native artifacts;
no generated files or credentials enter commits. No immutable signature is regenerated.
