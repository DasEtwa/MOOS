# MOOS Native N3 acceptance — 2026-10-02

MOOS Native N3 provides a bootable, locally guided offline installer with a typed
and revalidated disk plan, per-install storage identities, explicit destructive
confirmation, verified Core installation and a tested preserve-DATA reinstall
path on disposable QEMU-backed targets. It is experimental, not production
installation readiness or physical-hardware acceptance.

## Architecture and artifacts

The separate Buildroot target carries a Rust installer, kernel and gzip
initramfs on raw GPT media: protective MBR, 1 MiB BIOS_GRUB at 1 MiB and a
128 MiB INSTALLER/ESP at 2 MiB. The 131 MiB image boots through real GRUB BIOS
and UEFI disk paths. Runtime state is ephemeral RAM; all Core payload bytes
remain on the readonly FAT source. Installation needs no network. There is no
login/getty/root-shell interface, Python runtime or remote installer operation.

The installer ELF is about 725 KiB and compressed runtime about 16.6 MiB.
The schema-1 manifest binds six exact role/file/size/SHA-256 entries: BOOT,
SYSTEM_A, BIOS_BOOT, BIOS_CORE, KERNEL and UEFI. Hashes are integrity checks,
not publisher authentication. No private key, PR #41 dependency or signed
production Native provenance was introduced. Generated artifacts/logs/private
test targets remain ignored; no GitHub Release is published.

Installed targets require 192 MiB–64 GiB, whole-MiB size and 512-byte logical
sectors. All partitions align to 1 MiB:

| Role | Offset / size | Installed behavior |
| --- | --- | --- |
| BIOS_GRUB | 1 MiB / 1 MiB | Standard GRUB GPT embedding |
| BOOT/ESP | 2 MiB / 16 MiB | BIOS config, kernel, UEFI fallback loader; no NVRAM writes |
| SYSTEM_A | 18 MiB / 60 MiB | Exact locked-release Core payload; writable |
| SYSTEM_B | 78 MiB / 60 MiB | Zero-filled/unformatted, no-automount, reserved; no A/B logic |
| DATA | 138 MiB / remainder minus final MiB | Persistent state; 373 MiB on tested 512 MiB targets |

Fresh install uses CRNG-ready OS randomness for independent UUIDv4 disk, five
partition and installation IDs. Installed GRUB searches a full unique BOOT-GUID
marker and uses the unique SYSTEM_A PARTUUID. BIOS initially uses the
firmware-selected disk, including when it is the second disk. DATA retains the
N2 filesystem UUID/label but is selected only on the actual system disk.
DATA schema stays 1, with root-owned private identity/config directories and
0600 schema/installation-ID files. No ID is baked into distribution bytes.

Preserve mode accepts only recognized unique installed N3 layouts and valid
supported DATA state. It preserves all GPT IDs, installation ID and the entire
DATA filesystem bytes; BOOT, SYSTEM_A and reserved SYSTEM_B may be replaced.
The fixed-GUID N2 distribution is not an installed preserve target. Unsupported,
foreign, damaged or ambiguous state does not fall back to erase.

## Safety and observed VM evidence

Discovery uses bounded kernel/sysfs facts: model/serial/WWN where available,
size, sector sizes, flags, device number, canonical sysfs parent, diskseq,
partition roles and current-layout hashes. Virtio model/WWN were unavailable
in this QEMU configuration and are reported as such. Eligibility requires QEMU
DMI, virtio_blk, a unique explicit `MOOS-N3-TARGET-` test serial, writable status
and sufficient space. The source is resolved by its exact installer PARTUUID
and must be uniquely distinguishable and readonly.

An internal immutable plan binds target fingerprint, mode, size/layout, payload
hashes/version, future GPT IDs and destructive summary. Confirmation is exactly
`confirm ERASE <16-hex-plan-digest>` or the separate `confirm PRESERVE ...`.
Plans expire after 120 seconds and are consumed on attempts/cancel/change.
Target and payload are re-read before mutation; opened whole/partition
descriptors and generations are retained/rechecked. Cache invalidation is
limited to eligible unmounted target descriptors, never source media.

The Host harness runs unprivileged under Bubblewrap/TCG with pinned regular
file bindings. Only private single-link 0600 target files under a test-owned
0700 temporary directory are writable. Devices, symlinks, hardlinks, canonical
images and source/target inode aliases are rejected. Firmware/source are readonly;
there is no passthrough, Host checkout mount, network or arbitrary QEMU argument.

COMPLETE follows exact primary/backup GPT, roles/GUIDs, BIOS bytes, BOOT
configs/kernel/EFI, SYSTEM_A hash, reserved B, DATA/schema/ID and Core lock/version
verification. Written Core is checked for absence of installer/test-only files
and Python. Independent disk boot is tested separately. Preserve logs omit
WRITING_LAYOUT and INITIALIZING_DATA. Fresh failure can leave an unbootable
target; preserve failure can damage replaceable system/boot slots. Neither mode
claims full power-loss recovery. Normal Native boot still never formats DATA.
